# 実装計画

シミュレータとアセンブラの実装計画。段階の区切りと完了条件は `CLAUDE.md` の「実装の順番と完了条件」に合わせている。仕様の正は `docs/spec.md`。

- 終わった項目は `[x]` にする。
- `→ T-xx` は、先に人間が決めることが必要な項目（`docs/todo.md` の番号）。決まるまでは仮の動作で実装し、コメントに `TODO(T-xx)` を書く。
- 各段階の終わりに `npm test` を通し、`CLAUDE.md` の「現在の状況」を更新する。

## 段階2　1スレッドの命令実行

完了条件：基本命令32種とSYS拡張がすべて仕様通りに動き、命令ごとのテストが通る。

### 2.1 メモリ（`sim/memory.js`）

- [x] 番地の振り分け：割り当てなし（0x0000_0000〜0x000F_FFFF）、ローカルBSRAM（コアごとの64KBの窓）、外部RAM（8MB）、I/O、ブートROM（4KB）
- [x] 32bit・8bitの読み書き（リトルエンディアン）
- [x] 4バイト境界の検査（`@`、`!`、`XCHG`、`EXEC`、命令フェッチ）→ 例外10
- [x] 割り当てのない番地、ローカルの窓のうち実装容量の外 → 例外11（T-14）
- [x] ブートROMへの書き込み → 例外12
- [x] 外部RAM・ローカルBSRAMの初期値は0（T-15）
- [x] 命令フェッチは自コアのローカルBSRAMとブートROMからだけ → それ以外は例外7
- [x] I/O領域は、段階5までは「デバイスを登録できる口」だけ作る（未登録はバスエラー）
- [x] I/Oへの8bitアクセスは、テキストVRAM・フォントRAM・保護キー表だけ。他は例外10（T-16）
- [x] `Machine.load(address, bytes)`（イメージの直接読み込み、11.2節）

### 2.2 スレッドの状態（`sim/thread.js`）

- [x] PC、命令語バッファ、スロット番号、T・Nを含むデータスタック、リターンスタック、UP、モード、イベントのラッチ、スレッドごとのCSR
- [x] リセット時の状態（11.1節）：PC＝0xFFFF_0000、特権モード、DSP・RSP＝0、UP＝0、VBR＝0xFFFF_0100
- [x] スタックはTとNを含めた総数で数える（6.2.1節）

### 2.3 フェッチと実行（`sim/core.js`）

- [x] 語のフェッチ：`decodeWord` でデコードし、例外4・5をフェッチ時に判定
- [x] 1回の番に1スロットずつ実行し、命令語バッファとスロット番号を保持する（6.1節、語の途中でのブロックに備える）
- [x] 「次の語」の計算（その語が消費した定数語の後ろ）
- [x] 埋め草のNOPも1スロット＝1回の番として実行する（T-10）
- [x] slot6の実行（01＝RET、10＝+、11＝DUP、仮）
- [x] 段階2での例外の仮の扱い（`raise`）：ECAUSE・EPC・EIR・ESLOT・EADDRを記録してスレッドを止める（本格的な入口は段階4）
- [x] 仮想時間：サイクル数から `microseconds` を計算する（9K＝54MHz、20K＝72MHz。T-11）

### 2.4 基本命令（4章）

- [x] NOP、LIT、SLIT（符号付き5bit）、UA（`UP | (n<<2)`）
- [x] JMP、JZ、CALL（分岐先＝語のアドレス＋オフセット×4、32bitで一周しない）。範囲外は仮に例外7 → T-80
- [x] RET（下位2bitが0でなければ例外10、後ろのスロットは実行しない）
- [x] EXEC（4バイト境界、戻り先は次の語）
- [x] `>R`、`R>`、`R@`、DUP、DROP、SWAP、OVER
- [x] `+`、`-`、AND、OR、XOR、LSHIFT、RSHIFT（シフト量は下位5bit、論理シフト）
- [x] UM\*（符号なし64bit、結果は lo hi の順）
- [x] `=`、`<`（符号付き）、`U<`（符号なし）。真＝−1、偽＝0
- [x] `@`、`!`、`C@`（ゼロ拡張）、`C!`
- [x] 命令ごとのテスト（スタック効果と結果）

### 2.5 SYS拡張（5章）

- [x] TID（tidの形式、6.3節）
- [x] FENCE（何もしない）、XCHG（アトミック、4バイト境界）
- [x] PCREL（オフセット語自身のアドレス＋オフセット）
- [x] UP@、UP!（128バイト境界でなければ例外10、特権）
- [x] SP@・RP@（実行する直前の深さ）、SP!・RP!（増やした段は以前の値、なければ0。範囲外の値は次の語のフェッチ時に例外。T-12、T-13）
- [x] HALT（スレッドを止める。再開はTHREADCTLによるリセットだけ。T-17）
- [x] CSR@・CSR!：CSRの表（8章）、一般モードはCSR@ #0〜#9だけ（他は例外6）、読み出し専用のCSRへの書き込みは例外4（T-18）
- [x] INSTRETは実行したスロット数（NOPとslot6を含む。T-19）、ISAVER＝`ISA_VERSION`（仕様書の版と一致、現在0x0003。T-20）
- [x] M\*（符号付き）、U/MOD、/MOD、UM/MOD（0除算、0方向への切り捨て、−2³¹÷−1、UM/MODのあふれの余りは0。T-21）
- [x] 拡張命令がハードウェアにない構成（FEATURES）では、そのスロットまで実行してから例外18
- [x] BRK → 例外9、SYSCALL → 例外8、RETI（段階4で完成。段階2では戻り先とモードを戻すところまで）
- [x] 特権命令を一般モードで実行 → 例外6（フェッチ時に判定）
- [x] WAIT、SIGNAL、SENDM、SENDM?、RECV は段階3（段階2では「未実装（段階3）」のエラーを投げる）
- [x] 命令ごとのテスト

- [x] 1回の番で1命令（オペランド用のスロットは番を使わない。T-81）
- [x] フェッチ時のスタック深さの判定（段階4の4.2節を前倒し。slot6も含める → T-01）

### 2.6 テスト用の道具

- [x] テストの補助関数（`test/helpers.js`）：ソースをアセンブルして読み込み、HALTまで実行し、スタック・メモリ・CSRを確かめる

## 段階3　バレル、イベント、WAIT、メールボックス

完了条件：実行可能なスレッドだけのラウンドロビン（間隔D＝4、足りなければ空サイクル）、待機状態、SENDM・RECVが動く。

### 3.1 スケジューラ

- [ ] コアごとに、実行可能なスレッドだけでラウンドロビン（方式1）
- [ ] 同じスレッドはD（＝4）サイクル以上あける。足りなければ空サイクル
- [ ] 回る順番と開始位置：tidの小さい順、前に発行したスレッドの次から。リセット直後はスレッド0から（T-22）
- [ ] 20K（2コア）：1サイクルごとにコア0、コア1の順に1回ずつ進める（T-23）
- [ ] 待機状態（WAIT、RECV、SENDのブロック、除算・メモリ待ち、HALT）と THREADSTAT の値（12.7.5節）
- [ ] 語の途中でブロックしたら、再開時に続きのスロットから実行する

### 3.2 時間のかかる操作

- [ ] 除算器：1コアに1個、32サイクル、発行したスレッドだけ待機。除算器が使用中なら発行順に待たせる（T-24）
- [ ] 外部RAMへのアクセスの待ち時間：8サイクル（構成で変更可。T-25）
- [ ] 他コアのローカルBSRAMへのアクセスの待ち時間：2サイクル（構成で変更可。T-25）

### 3.3 イベントとWAIT（6.4節）

- [ ] イベントのラッチ（スレッドごと）。デバイスのイベントは全スレッドに立てる
- [ ] ビット0（メールボックス）、4・5（UART）は状態をそのまま表す
- [ ] WAIT ( mask -- bits )：立っているビットを返して消す。mask＝0はスレッドの停止で、再開はTHREADCTLによるリセットだけ（T-26）
- [ ] SIGNAL：相手のビット1を立てる。tid＝−1で全スレッド（自分を含む。T-27）。存在しないtidは例外14
- [ ] EVPEND（CSR 9）

### 3.4 メールボックス（10章）

- [ ] スレッドごとのFIFO（深さはMBOXDEPTH）
- [ ] SENDM #n：n＋1語の空きができるまで待ち、ヘッダ（送信元tid、tag、n）＋n語をまとめて送る
- [ ] SENDM? #n：空きがなければ送らずに偽。成否にかかわらず引数を消費する
- [ ] RECV：1語受け取る。空なら待つ
- [ ] 同じ送信元から同じ相手への順序の保証
- [ ] 待っている送信者が複数いるときは、待ち始めた順に送る（T-28）
- [ ] 存在しないtidへの送信は例外14。自分自身への送信も許す（T-29）
- [ ] テスト：2スレッドの往復、FIFOが一杯のときのブロックとSENDM?

## 段階4　例外、スタック深さの判定、保護キー

完了条件：例外表（7.2節）のすべての例外をテストで起こせる。

### 4.1 例外の入口と出口（7.3節）

- [ ] 戻り先（語のバイトアドレス、bit0＝モード）をリターンスタックに積み（レッドゾーンを使う）、特権モードにしてVBR＋番号×4へ
- [ ] ECAUSE、EPC、EIR、ESLOT、EADDR の記録（フェッチ時の例外のESLOT、EADDRの値 → T-30）
- [ ] 再開できる例外は語の先頭から、例外8・18は次の語から
- [ ] RETI：戻り先とモードを戻す（一般モードでは例外6）
- [ ] 二重例外（例外15）の条件 → T-31。ハードウェアでスレッドを停止（THREADSTAT＝7）
- [ ] 同じ語で複数の例外が起きるときの優先順位 → T-32

### 4.2 スタック深さの判定（6.2.1節、7.1節）

- [x] 語のフェッチ時に、スロットごとの増減を累積し、最大値・最小値で判定する（段階2で実装済み）
- [x] SENDM・SENDM?の増減は −(n＋2)。SP!・RP!で範囲外にした深さは次の語で判定（段階2で実装済み）
- [ ] slot6を判定に含めるか → T-01
- [x] データスタック：容量を超えたら例外0、0未満で例外1（段階2で実装済み）
- [x] リターンスタック：容量−3を超えたら例外2、0未満で例外3（段階2で実装済み）
- [ ] 例外の入口のプッシュは判定の対象外

### 4.3 保護（9.4節）

- [ ] 保護キー表（I/Oの0xFF08_0000、外部RAM 2048ページ、コアごとのローカルBSRAMの表）
- [ ] 一般モードの判定：読み出し（PKREAD）、実行（PKREAD かつ X）、書き込み（PKWRITE かつ W）→ 例外12
- [ ] PKREAD・PKWRITEのビットの意味（ビットn＝キーn）→ T-33
- [ ] ブートROMのページの権限 → T-34（仕様書14.1節）
- [ ] I/Oはユーザーページ以外、一般モードからアクセスできない → 例外12
- [x] 他コアのローカルBSRAMへのXCHG → 例外13（段階2で実装済み）
- [x] 命令フェッチ違反（例外7）、バスエラー（例外11）（段階2で実装済み。ローカルの容量の外からのフェッチも例外7。T-82）

### 4.4 テスト

- [ ] 例外0〜15、18をそれぞれ起こすテスト（16・17は予約なので起きないことを確かめる）
- [ ] 再開できる例外からRETIで戻り、正しく続きを実行できること
