# UARTからの操作マニュアル

UART（シリアル）を使って、ミニパソコンの起動の様子を見たり、ROMのモニタでレジスタやメモリを調べたりする方法をまとめたもの。
動作の正は `docs/spec.md`（7.4節・11章・12.3節）と `rom/boot.asm`。この文書は使い方の説明だけを扱う。

## 1. つなぎ方

### 1.1 シミュレータ

1. `npm run serve` を実行し、ブラウザで `http://localhost:8000/` を開く。
2. 右上のタブで **UART** を選ぶ。
3. 黒い端末の部分をクリックすると、キーボードの入力がUARTの受信に送られる（端末の枠が青くなる）。

| キー | 送られる値 |
|---|---|
| 文字のキー | その文字（ASCII） |
| Enter | 13（CR） |
| Backspace | 8 |
| Tab | 9 |
| Esc | 27 |

- 受け取った文字は、送信の速さ（115,200bps相当、1文字に約87マイクロ秒の仮想時間）で1文字ずつ届く。実行を止めていると届かないので、**実行中（▶ 実行を押した状態）に入力する**。
- 「消去」で表示を消せる（UARTの中身には影響しない）。

### 1.2 実機（Tang Nano 9K・20K）

| 項目 | 設定 |
|---|---|
| 接続 | 基板のUSB（9KはBL702、20KはBL616のUSBシリアル） |
| 速さ | 115,200bps |
| 形式 | 8N1（データ8bit、パリティなし、ストップ1bit）、フロー制御なし |
| 改行 | 受信：CR LF で表示する設定にする。送信：Enterで CR（13）を送る設定にする |
| 端末ソフト | Tera Term、screen、minicom など |

例（macOS・Linux）：`screen /dev/tty.usbserial-XXXX 115200`

## 2. 起動したときの表示

リセットすると、tid 0 がブートROMの boot を実行し、UARTに次のように出す（11.2節）。

```
Welcome to Stack CPU
```

続いて外部RAMを簡単に検査し、問題がなければOSイメージ（コア0のローカルBSRAMの先頭、0x0010_0000）へ移る。OSが何も出さなければ、表示はこの1行だけになる。

### 2.1 外部RAMの検査で食い違ったとき

```
Welcome to Stack CPU
RAM ERROR $01000000

*** MONITOR TID=00000000
...
```

- `$` の後は、最初に食い違った番地（16進）。データ線の故障なら先頭（$01000000）、アドレス線の故障なら食い違った番地が出る。
- 基板のLEDが 101010（0x2A）になり、ROMのモニタに入る（3章）。
- OSは起動しない。

### 2.2 OSイメージがないとき

OSイメージを読み込まずにブートROMから起動すると、空のローカルBSRAM（中身は0＝NOP）を最後まで実行し、その先のフェッチで例外7になって、モニタに入る。

```
Welcome to Stack CPU

*** MONITOR TID=00000000
ECAUSE=00000007 EPC=00106000 EIR=00000000 ESLOT=00000000 EADDR=00106000
> 
```

## 3. ROMのモニタ

### 3.1 モニタに入るとき

| きっかけ | 説明 |
|---|---|
| カーネル（tid 0）の例外 | 再開しない例外やスタックのあふれ（例外0〜7、10〜17）がカーネル自身で起きたとき |
| BRK命令 | どのスレッドでも |
| SYSCALL 3（MONITOR） | プログラムから呼ぶ：`PUSHQ #3` `TRAP` |
| 外部RAMの検査の食い違い | 起動時（2.1節） |

カーネル以外のスレッドの例外ではモニタに入らず、カーネルに FAULT のメッセージが送られて、そのスレッドが止まる。

入ったときの表示：

```

*** MONITOR TID=00000000
ECAUSE=00000008 EPC=00100004 EIR=FB800000 ESLOT=00000000 EADDR=00000000
> 
```

- `TID=` はモニタに入ったスレッド。
- 2行目は、最後に起きた例外のレジスタ（3.3節の `R` と同じ）。
- `> ` がプロンプト。ここでコマンドを打つ。

### 3.2 コマンドの一覧

コマンドは**1文字**で、押した瞬間に実行される（Enterは要らない）。英小文字でもよい。CR・LF・空白は無視する。
打った文字はエコーされる。

| コマンド | 動作 |
|---|---|
| `R` | レジスタを表示する |
| `S` | モニタに入ったときのデータスタックを表示する |
| `D 番地`＋Enter | その番地からメモリを4語×2行表示する |
| `G` | 続行する（モニタに入ったところに戻る） |
| `T` | 外部RAMの全域を検査する |
| その他 | `?` を表示する |

### 3.3 R：レジスタ

```
> R
ECAUSE=00000008 EPC=00100004 EIR=FB800000 ESLOT=00000000 EADDR=00000000
```

| 表示 | 意味 |
|---|---|
| ECAUSE | 例外の番号（3.8節の表） |
| EPC | 例外が起きた命令語の番地 |
| EIR | その命令語 |
| ESLOT | 原因の命令のスロット番号（0〜6） |
| EADDR | 問題になった番地（番地に関係しない例外では0） |

値はすべて16進8桁。BRK・SYSCALLでモニタに入ったときは、その例外（9・8）の記録になる。

### 3.4 S：データスタック

```
> S
SP=00000002
00000005 00000006 
```

- `SP=` は深さ（要素の数）。
- 次の行は、下（最初に積んだもの）から順の要素。一番右がT（一番上）。
- モニタは入ったときにデータスタックを作業領域（外部RAMの最後の4KB）に退避しており、`S` はその中身を表示する。
- カーネルの例外で入ったときは、ハンドラがスタックを空にしてから入るので、`SP=00000000` になる。

### 3.5 D：メモリのダンプ

`D` に続けて番地を16進で打ち、Enterで実行する。

```
> D 100000
00100000: B96E6B8C FB800000 77E00000 00000000
00100010: 00000000 00000000 00000000 00000000
```

- 番地は4バイト境界に切り下げる。
- 16進の数字（0〜9、A〜F、a〜f）以外の文字（空白など）は無視する。
- **Backspaceでの訂正はできない**。打ち間違えたら、いったんEnterで実行してから打ち直す。
- 割り当てのない番地（例：$00000000）を指定すると、モニタの中でバスエラーになり、モニタに入り直す。

### 3.6 G：続行

```
> G

```

- 退避したデータスタックを戻して、モニタに入ったところへ戻る（RETI）。
- SYSCALL 3（MONITOR）で入ったときは、`TRAP` の次の語から続く。
- **BRKで入ったときは、同じBRKをもう一度実行して、すぐにモニタに戻る**（BRKの戻り先は語の先頭のため）。
- カーネルの例外や外部RAMの検査で入ったときは、続行するとスレッドが止まる（HALT）。

### 3.7 T：外部RAMの全域の検査

```
> T
RAM OK
```

- 外部RAMの全部の語に、番地とその反転を書いて読み戻す。食い違えば `RAM ERROR $番地` を表示する。
- モニタの作業領域（外部RAMの最後の4KB）は検査しない。
- 外部RAMの中身は書き換わる。
- 8MBの検査には時間がかかる（実機の9Kで数秒、シミュレータの「最高速」ではさらにかかる）。

### 3.8 例外の番号（ECAUSE）

| 番号 | 例外 | 番号 | 例外 |
|---|---|---|---|
| 0 | データスタックのオーバーフロー | 10 | アドレスの境界違反 |
| 1 | データスタックのアンダーフロー | 11 | バスエラー |
| 2 | リターンスタックのオーバーフロー | 12 | 保護違反 |
| 3 | リターンスタックのアンダーフロー | 13 | リモートXCHG違反 |
| 4 | 不正命令 | 14 | 不正なスレッド番号 |
| 5 | 配置違反 | 15 | 二重例外 |
| 6 | 特権違反 | 16・17 | 予約 |
| 7 | 命令フェッチ違反 | 18 | 未実装命令 |
| 8 | SYSCALL | | |
| 9 | ブレークポイント（BRK） | | |

詳しくは `docs/spec.md` の7.2節。

### 3.9 注意

- モニタは同時に1つのスレッドだけが使う前提。複数のスレッドが同時に入ると、表示と作業領域が混ざる。
- データスタックが一杯（16段）のときに入ると、退避の途中であふれる。

## 4. プログラムからUARTを使う

### 4.1 SYSCALL（一般モードでも使える）

ブートROMのSYSCALLで、1文字ずつ送受信できる（11.4節）。

| 番号 | 名前 | スタック効果 | 書き方 |
|---|---|---|---|
| 1 | DPUTC | ( c -- ) | `PUSH #$41` `PUSHQ #1` `TRAP`（'A'を送る） |
| 2 | DGETC | ( -- c ) | `PUSHQ #2` `TRAP`（1文字届くまで待つ） |
| 3 | MONITOR | ( -- ) | `PUSHQ #3` `TRAP` |

例：受け取った文字をそのまま送り返す。

```
start:  PUSHQ #2
        TRAP          ; ( c )      DGETC
        PUSHQ #1
        TRAP          ; ( )        DPUTC
        BRA   start
```

文字列を送る例は `examples/06_start.asm` の `tputs`。

### 4.2 レジスタを直接使う（特権モードだけ）

| 番地 | 名前 | 内容 |
|---|---|---|
| $FF000000 | DATA | 書く：下位8bitを送る。読む：下位8bitが受信データ（bit31＝1なら受信データなし） |
| $FF000004 | STATUS | bit0＝受信データあり、bit1＝送信FIFOが一杯、bit2＝送信がすべて完了、bit3＝受信あふれ |
| $FF000008 | DIV | 分周比（クロック÷通信速度） |

- 送信FIFOが一杯のときに書いた文字は捨てられるので、STATUSのbit1が0になるのを待ってから書く（`examples/03_uart_puts.asm`）。
- 受信データを待つときは、ポーリングの代わりに `PUSH #16` `WAIT`（イベント4）で待てる。
- 詳しくは `docs/spec.md` の12.7.1節。

## 5. 困ったとき

| 症状 | 確かめること |
|---|---|
| 何も表示されない（シミュレータ） | UARTのタブを開いているか。実行中か。ブートROMから起動したか（直接実行では起動メッセージは出ない） |
| 何も表示されない（実機） | 速さが115,200bps・8N1か。正しいシリアルポートを開いているか |
| キーを押しても反応しない（シミュレータ） | 端末の部分をクリックしたか（枠が青い）。実行を止めていないか |
| 改行が崩れる（実機） | 端末ソフトの改行の設定（受信はCR LF） |
| `D` の番地を打ち間違えた | Enterで実行してから打ち直す（訂正はできない） |
| `G` を押すとすぐにモニタに戻る | BRKで入っている（3.6節）。シミュレータなら、BRKの代わりにUIのブレークポイントを使う |
