# シミュレータの画面（UI）の仕様（案）

ブラウザで動くシミュレータの画面の仕様。CPUとマシンの仕様は `docs/spec.md` を正とし、この文書は画面と操作だけを扱う。
2026-11-14 の相談で決めた方針（T-50〜T-55）をまとめたもの。細かい見た目は作りながら調整する。

## 1. 方針

| 項目 | 決めたこと |
|---|---|
| 主な目的 | スレッドごとの逆アセンブルとスタックの様子を観察する |
| 配置 | 「一覧＋詳細」と「全スレッドの格子」を切り替えられる（T-50） |
| 実行の制御 | 通常の実行と停止、4種類のステップ実行、ブレークポイント（T-51） |
| 実行の速さ | 実時間・最高速・ゆっくりを切り替えられる（T-52） |
| プログラムの入力 | ローカルのファイルをブラウザに読み込む。.asm・.bin・.hex（T-53） |
| 起動の仕方 | 「ブートROMから起動」と「tid 0 で直接実行」を、読み込むときに選ぶ（T-53） |
| 機種 | 9K・20Kを画面で切り替える（T-54） |
| 入力 | フォーカスで切り替え：UART端末ではキーをUARTへ、画面ではキーをジョイパッドへ（T-55） |
| 想定する画面の大きさ | 横1280ドット以上のパソコンのブラウザ |

## 2. 全体の配置

```
+------------------------------------------------------------------------------+
| ツールバー：[開く] 機種[9K▼] [リセット] [実行/停止] ステップ[1命令][1語][飛ばす][1サイクル] |
|             速さ[実時間▼]  表記[レジスタ風▼]  表示[一覧＋詳細 | 格子]           |
| 状態：サイクル 1,234,567  仮想時間 22,862 µs  停止の理由：ブレークポイント $00100010 (tid 1) |
+------------+-----------------------------------+-----------------------------+
| スレッド   | 詳細（選んだスレッド、最大4列）     | 右のタブ：[画面][UART]       |
| の一覧     |  tid 0          | tid 1           |                             |
|            |  逆アセンブル   | 逆アセンブル    |                             |
|            |  スタック       | スタック        +-----------------------------+
|            |  情報           | 情報            | 下のタブ：[メモリ][CSR]      |
|            |                 |                 | [メールボックス][BP][ログ]  |
+------------+-----------------+-----------------+-----------------------------+
```

- 「格子」に切り替えると、中央の「一覧＋詳細」の部分が全スレッドの格子になる（右側のタブはそのまま）。
- 右側の2つのタブの領域は、幅を変えたり、たたんだりできる。

## 3. ツールバーと状態

| 部品 | 動作 |
|---|---|
| 開く | ファイルを選ぶと、読み込みの画面を出す（6章） |
| 機種 | 9K・20Kを選ぶと、マシンを作り直して、最後に読み込んだファイルを読み込み直す |
| リセット | マシンをリセットし、最後に読み込んだファイルを読み込み直す |
| 実行／停止 | 通常の実行を始める・止める。実行中もブレークポイントで止まる |
| ステップ | 4種類（5章）。ステップの対象は「選んでいるスレッド」 |
| 速さ | 実時間（仮想時間＝実時間）、最高速、ゆっくり（毎秒n命令、nは1〜1000） |
| 表記 | 逆アセンブルの表記：レジスタ風・Forth風 |
| 表示 | 一覧＋詳細・格子 |
| 状態 | サイクル数、仮想時間（マイクロ秒）、止まった理由（ブレークポイント、例外、ステップの終わり、全スレッドが停止など）。実行中に、動けるスレッドがなくUARTの受信を待っているだけのときは「入力を待っています（UART）」 |

## 4. スレッドの表示

### 4.1 一覧＋詳細

**スレッドの一覧**（左）：1スレッド1行。20Kではコアごとに見出しを付けて分ける。

| 列 | 内容 |
|---|---|
| tid | スレッド番号（16進） |
| 状態 | THREADSTATの名前（リセット直後、実行中、WAIT、RECV待ち、SEND待ち、除算・メモリ待ち、HALT、二重例外） |
| モード | 特権・一般 |
| PC | 実行中の語の番地とスロット番号 |
| D | データスタックの深さ／容量 |
| R | リターンスタックの深さ／容量 |
| T・N | データスタックの一番上と2番目 |
| 命令数 | INSTRET |

行をクリックすると、そのスレッドを選ぶ（ステップの対象になる）。行の「ピン」を押すと、詳細の列に加わる（最大4列。選んでいるスレッドは常に表示）。

**詳細の列**（中央）：1スレッド1列。上から次の3つ。

1. **逆アセンブル**
   - 実行中の語を中央にして前後の語を表示し、実行に合わせて追いかける（追いかけを止めてスクロールもできる）。
   - 1行が1語：番地、命令語の16進、逆アセンブル、ラベル（.asmから読み込んだとき）、ソースの行（同）。
   - 次に実行するスロットの命令を強調する。LIT・PCRELの定数語は、命令語の下に薄く表示する。
   - 行の左端をクリックすると、その番地にブレークポイントを置く・外す。
2. **スタック**
   - データスタック：上がT。全段を表示し、深さ／容量の棒を付ける。直前のステップから変わった値を強調する。
   - リターンスタック：同様。容量を超えた3段（レッドゾーン）は色を変える。
3. **情報**：UP、モード、EVPEND（立っているイベント）、メールボックスにたまっている語数、最後に起きた例外（番号、EPC、EADDR）。

### 4.2 格子

- 全スレッドを小さな枠で格子状に並べる（9Kは4×2、20Kはコアごとに4×2を2つ）。
- 各枠：tid、状態、PC、逆アセンブル数行、データスタックの上の4段、深さの棒。
- 枠をクリックすると、そのスレッドを選んで「一覧＋詳細」に切り替える。

## 5. ステップ実行

ステップの対象は選んでいるスレッド（「1サイクル」だけは全体）。ステップの間も他のスレッドは動き、ブレークポイントにかかれば途中で止まる。

| 種類 | 動作 |
|---|---|
| 1命令 | 選んだスレッドが次に1命令を実行し終えるまで、全体を進める |
| 1語 | 選んだスレッドが今の語を最後まで実行する（または分岐する）まで進める |
| 飛ばす | 次の命令がCALL・EXECなら、呼んだ先から戻る（リターンスタックが元の深さに戻り、次の語に来る）まで進める。それ以外は「1命令」と同じ |
| 1サイクル | マシン全体を1サイクルだけ進める（どのスレッドが発行したか、空サイクルかが見える） |

- 選んだスレッドが待機中（WAIT、RECV待ちなど）や停止中で、いつまでも終わらないときは、一定のサイクル数で打ち切って知らせる。

## 6. ファイルの読み込み

| 形式 | 読み込み方 |
|---|---|
| .asm | ブラウザでアセンブルする。誤りは行番号つきで表示する。ORGがあればその番地、なければ0x0010_0000。ラベルとソースの行を逆アセンブルの表示に使う |
| .bin | リトルエンディアンのバイナリ（`tools/asm.js -o`）。読み込む番地を指定する（既定0x0010_0000） |
| .hex | `$readmemh` 形式（`tools/asm.js --hex`）。読み込む番地を指定する（既定0x0010_0000） |

読み込みの画面で、起動の仕方を選ぶ。

| 起動の仕方 | 動作 |
|---|---|
| ブートROMから起動 | プログラムをOSイメージとして0x0010_0000に置き、リセットからブートROMを通る（実機と同じ流れ）。番地が0x0010_0000でなければ知らせる |
| tid 0 で直接実行 | ブートROMも読み込むが、tid 0 だけは起動の処理を飛ばして、プログラムの先頭から特権モードで始める（他のスレッドはブートROMのidleで待つ）。UPを指定できる（既定は0x0010_5F80：ローカルBSRAMの最後の128バイト） |

ブートROM（`rom/boot.asm`）は、UIを開いたときにアセンブルして組み込む。

## 7. ブレークポイント

どれもメモリを書き換えず、シミュレータの側で止める（CPUのBRK命令とは別）。下のタブ「BP」で一覧・有効／無効・削除ができる。

| 種類 | 止まる時点 |
|---|---|
| 命令語の番地 | どれかのスレッドが、その番地の語を実行し始める直前（全スレッド共通） |
| 例外 | 選んだ番号の例外が起きて、入口の処理（戻り先を積んでベクタへ移る）を終えた直後。番号ごとにオン・オフ |
| メモリへの書き込み | 指定した番地（4バイト単位）に、どれかのスレッドが書き込んだ直後（`!`、`C!`、XCHG） |

- 止まった後に続けると、止まった原因の語・命令からそのまま進む（同じブレークポイントですぐに止まり直さない）。

## 8. 右と下のタブ

| タブ | 内容 |
|---|---|
| 画面 | テキスト画面（640×480）。倍率は1倍・0.5倍・合わせる。下にジョイパッドのボタン。クリックするとキーがジョイパッドに割り当てられる |
| UART | 送信された文字の表示。クリックするとキー入力をUARTへ送る。消去ボタン |
| メモリ | 番地を入れて16進でダンプ（語・バイトの切り替え）。実行中は定期的に更新 |
| CSR | 選んだスレッドのCSR（8章の表のすべて） |
| メールボックス | 選んだスレッドの受信FIFOの中身（ヘッダを分解して表示）と、そのスレッドへの送信を待っているスレッド |
| BP | ブレークポイントの一覧と設定 |
| ログ | 例外、止まった理由、UARTの送受信などの出来事 |

### 8.1 変わった箇所の強調

プログラムの流れを追いやすくするため、ステップ・実行を始めた時点から変わった値に背景色を付ける（ゆっくりのときは、直前に実行した命令の分だけ）。

| 場所 | 強調するもの |
|---|---|
| スレッドの一覧 | 状態、D、R、T |
| 詳細の列 | スタックの値、情報のUP・EVPEND・メールボックスの語数・最後の例外 |
| メモリ | CPUが書き込んだ語・バイト（同じ値を書いても強調する。覚えるのは8,192語まで） |
| CSR | 値が変わったCSR |
| メールボックス | 新しく届いた語、語数、送信を待っているスレッド |

## 9. 入力

| フォーカス | キー |
|---|---|
| UART端末 | 押したキーの文字をUARTの受信に入れる（Enterは13） |
| 画面 | 矢印＝上下左右、Z＝A、X＝B、Shift＝SELECT、Enter＝START（押している間だけ1） |

## 10. 作り方

- `sim/` と `asm/` はDOMに依存しないまま使う。ステップ実行とブレークポイントの仕組みは、DOMに依存しない `sim/debugger.js` に作り、Node.jsでテストする。
- `ui/` は表示と操作だけを受け持つ。外部ライブラリは使わない（CLAUDE.md）。
- 表示の更新は、実行中は描画の周期（requestAnimationFrame）ごと、止まったときは全部。
- 表示の設定（表記、配置、速さ、倍率、機種）は、ブラウザに覚えさせる（localStorage）。
- 状態と表示用のデータは `ui/session.js`、HTMLの組み立ては `ui/views.js`（どちらもDOM非依存でNode.jsでテストする）、DOMの操作は `ui/main.js`。
- UIでは、利用者がいつでもUARTに入力できるので、`Machine.hostInput` を true にする（UARTの受信を WAIT で待つスレッドがいれば、止まったと判定せずに実行を続ける）。
- ブラウザのコンソールから操作するための口 `window.stackcpu` を用意する（デバッグの補助）：
  `stackcpu.openFile(名前, 中身)`（読み込みの画面を開く）、`stackcpu.loadText(名前, ソース, { boot, addr, up })`、`stackcpu.session`。
- ショートカット：F5＝実行／停止、F10＝1命令、F11＝飛ばす（入力欄・UART端末・画面にフォーカスがないとき）。

## 11. 当面作らないもの

- メモリ・レジスタ・スタックの値の書き換え
- 画面の上でのソースの編集
- 実行の履歴（トレース）を遡る機能
- 条件つきのブレークポイント
