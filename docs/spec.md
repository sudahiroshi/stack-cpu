## 1. 概要と設計方針

Tang Nanoシリーズ（当初は9Kと20K）で動かす、オリジナルCPUを含むミニパソコンの仕様。HDMIで画面に出力し、UART（当初のキーボード代わり）とジョイパッドを入力に使い、メッセージ型の簡易OSを動かす。

| 方針 | 内容 |
|---|---|
| CPU方式 | 32bitスタックマシン＋バレル（ハードウェアマルチスレッド） |
| OS | メッセージ型。カーネルは専用スレッド（tid 0）。ハードウェアスレッド＝タスク |
| 互換性 | 最下位から最上位の機種まで同じソフトが動く。構成の違いはCSRで申告する |
| リロケータブル | PC相対分岐とPCRELによる |
| リエントラント | スレッドごとのUP（ユーザー領域）とUAによる |
| 例外 | 割り込み・例外・戻りはすべて語の切れ目で扱う（案B） |
| メモリ | 単一アドレス空間。エイリアスなし |
| 保護 | ページごとの所有者キー＋スレッドごとのキー集合（PKREAD・PKWRITE） |

## 2. 基本仕様と構成パラメータ

### 2.1 基本仕様

| 項目 | 仕様 |
|---|---|
| データ幅 | 32bit（スタックの要素、ALU） |
| 命令語 | 32bit＝5bit×6スロット＋2bit |
| アドレス | 32bitのバイトアドレス |
| エンディアン | リトルエンディアン。64bit値は下位の語を小さい番地に置く |
| 境界 | 命令語・`@`・`!`・`XCHG`・`EXEC`の対象は4バイト境界 |
| 16bitアクセス | なし |
| 真偽値 | 真＝−1（全ビット1）、偽＝0 |
| キャリー | なし（多倍長の加算は `U<` で桁上がりを判定する） |
| シフト量 | 下位5bitで切る |

### 2.2 機種別の構成パラメータ

| パラメータ | 9K | 20K | 4K（将来） |
|---|---|---|---|
| コア数×1コアのスレッド数 | 1×8（合計8） | 2×8（合計16） | 1×4 |
| パイプラインの段数D | 4 | 4 | 4 |
| 目標クロック | 50〜60MHz | 60〜80MHz | 50MHz |
| スタックの段数 | 16 | 32 | 16 |
| ローカルBSRAM | 24KB | 24KB×2（要調整、2.4節） | 約6KB |
| メールボックス（1スレッドあたり） | 64語 | 64語（コアごとに512語を8スレッドで等分） | 128語 |
| 除算器 | あり | あり | なし（ソフトで代わりに実行） |
| 外部RAM | PSRAM 8MB | SDRAM 8MB | PSRAM（要確認） |
| 画面モード | 0、1（2は条件付き） | 0、1、2、3 | 0 |

- 4Kは、外部RAMからの命令実行（A3②）を実装する段階で対応する。
- RTLは全機種で共通にし、機種ごとの違いは合成時のパラメータで決める。

### 2.3 アプリケーションが前提にしてよい最小保証値

| 項目 | 保証値 |
|---|---|
| スレッドの合計 | 4以上 |
| スタックの段数 | 16以上 |
| メールボックス | 32語以上 |
| 外部RAM | 8MB（0x0100_0000〜） |
| 画面 | モード0（テキスト80×30、ASCII 0x20〜0x7E） |
| 拡張命令 | 全機種で使える（ハードウェアがない機種ではソフトで代わりに実行するので遅い） |

アプリは、自分がローカルBSRAMに置かれていることを前提にしない（4KではOSが外部RAMに配置するため）。

### 2.4 BSRAMの配分

BSRAMは1ブロック18Kbit。32bit幅で使うと1ブロック＝2KB。

| 用途 | 9K（26ブロック） | 20K（46ブロック） |
|---|---|---|
| ブートROM | 2 | 2 |
| データスタック | 1 | 2（コアごと） |
| リターンスタック | 1 | 2（コアごと） |
| スレッドごとの状態 | 1〜2 | 2〜4（コアごと） |
| メールボックス | 1 | 2（コアごと） |
| 保護キー表 | 1 | 1（2コアで共有） |
| 外部RAMのバッファ | 1 | 1 |
| テキストVRAM | 3 | 3 |
| フォントRAM | 2 | 2 |
| **ローカルBSRAM** | **12（24KB）** | **24（24KB×2）** |
| 残り | 0〜1 | 3〜5（ラインバッファ、モード2・3用など） |

**要調整**：20Kのローカルは以前「32KB×2」としていたが、CPU内部の分を計算に入れると46ブロックに収まらないため、24KB×2に修正した。20KはSSRAM（約41Kbit）に一部の状態を移せる可能性があり、合成後に確定する。4KのBSRAM容量は要確認。

## 3. 命令語の形式とオペランド規則

### 3.1 命令語の形式

```
 31    27 26    22 21    17 16    12 11     7 6      2 1  0
+--------+--------+--------+--------+--------+--------+----+
| slot0  | slot1  | slot2  | slot3  | slot4  | slot5  | s6 |
+--------+--------+--------+--------+--------+--------+----+
```

- 実行はslot0から順に、1回の番に1スロットずつ。
- slot6（2bit）は4種類の命令だけを置ける。符号は次の通り（01〜11は**仮**。使用頻度を見て決める）。

| slot6の値 | 命令 |
|---|---|
| 00 | NOP（確定） |
| 01 | RET（仮） |
| 10 | +（仮） |
| 11 | DUP（仮） |
- リトルエンディアンなので、命令語を `C@` で読むとslot0はaddr＋3のバイトに入っている。

### 3.2 オペランドの規則

| 規則 | 対象 | 内容 |
|---|---|---|
| ① 語の残りをすべて使う | JMP、JZ、CALL | 右側の残りのビットを符号付きPC相対オフセットとして使う。分岐の有無にかかわらず、その語の残りは実行しない |
| ② 次の1スロットを使う | SLIT、UA、SYS | 5bitのオペランド（SYSではサブ命令の番号） |
| ③ 次の語を使う | LIT、PCREL | 32bitの値。命令語の直後に、使う順に並べる |

SYSのサブ命令のうち、CSR@、CSR!、SENDM、SENDM?は、さらに次のスロットを即値として使う（SYSから数えて3スロット）。

### 3.3 分岐

- 分岐先＝**分岐命令を含む語のアドレス**＋オフセット×4（オフセットは語単位、符号付き）。
- オフセット0は同じ語の先頭へ戻る（1語のループ）。
- 同じ語にLITと分岐がある場合は、定数語を消費した後に分岐する。
- 「次の語」は、その語が消費した定数語の後ろを指す。JZで分岐しなかった場合と、CALLの戻り先がこれにあたる。

| 分岐の位置 | オフセット | 範囲（語単位） |
|---|---|---|
| slot0 | 27bit | ±64M語（±256MB） |
| slot1 | 22bit | ±2M語（±8MB） |
| slot2 | 17bit | ±64K語（±256KB） |
| slot3 | 12bit | ±2K語（±8KB） |
| slot4 | 7bit | ±64語（±256B） |
| slot5 | 2bit | 実用上は使わない |

分岐先が届かない場合、アセンブラが残りのスロットをNOPで埋め、分岐を次の語のslot0に移す。

- 分岐先の計算は**32bitで一周しない**（0xFFFF_FFFFを越えて0へ、または0を越えて0xFFFF_FFFFへは届かない）。アセンブラは番地どうしの実際の差でオフセットを計算し、収まらなければエラーにする。
- そのため、ブートROM（0xFFFF_0000〜）からローカルBSRAM（0x0010_0000〜）へは分岐では届かない。EXECかRETIで移る。

### 3.4 配置の規則（違反は全機種で例外5）

| 規則 | 対象 |
|---|---|
| 語の最後のスロットに置く | EXEC、SYSCALL、拡張命令（U/MOD、/MOD、UM/MOD、M*）、SP!、RP!（深さを任意の値に変えるため、後ろのスロットの深さをフェッチ時に判定できない） |
| オペランド用のスロットを確保できる位置に置く | SLIT、UA、SYS（slot5には置けない）、CSR@・CSR!・SENDM・SENDM?（さらに1スロット必要） |

拡張命令の配置は、ハードウェアがある機種でも検査する（ある機種では動き、ない機種では動かないプログラムを防ぐため）。

「語の最後のスロットに置く」は、**その命令より後ろのスロットが、slot6を含めてすべてNOP**であることを意味する。後ろがすべてNOPなら、語の途中に置いてもよい（アセンブラは後ろをNOPで埋める。13.2節）。

RET、RETIは語の途中に置いてもよいが、その後ろのスロットは実行しない（制御が移るため）。

## 4. 基本命令（32種）

記法：`( 実行前 -- 実行後 )`、右端がスタックの一番上（T）。`R:` はリターンスタック。

| 番号 | 命令 | スタック効果 | 備考 |
|---|---|---|---|
| 0 | NOP | ( -- ) | |
| 1 | LIT | ( -- n ) | 規則③ |
| 2 | JMP | ( -- ) | 規則① |
| 3 | JZ | ( flag -- ) | 0なら分岐。規則① |
| 4 | CALL | ( -- )  R:( -- ret ) | 規則① |
| 5 | RET | R:( ret -- ) | |
| 6 | EXEC | ( addr -- )  R:( -- ret ) | 間接呼び出し。語の最後に置く |
| 7 | >R | ( a -- )  R:( -- a ) | |
| 8 | R> | ( -- a )  R:( a -- ) | |
| 9 | R@ | ( -- a )  R:( a -- a ) | |
| 10 | DUP | ( a -- a a ) | |
| 11 | DROP | ( a -- ) | |
| 12 | SWAP | ( a b -- b a ) | |
| 13 | OVER | ( a b -- a b a ) | |
| 14 | + | ( a b -- a+b ) | |
| 15 | - | ( a b -- a−b ) | |
| 16 | AND | ( a b -- c ) | |
| 17 | OR | ( a b -- c ) | |
| 18 | XOR | ( a b -- c ) | INVERTは `-1 XOR` |
| 19 | LSHIFT | ( a n -- c ) | nは下位5bit |
| 20 | RSHIFT | ( a n -- c ) | 論理シフト。nは下位5bit |
| 21 | UM* | ( a b -- lo hi ) | 符号なし32×32→64bit。DSPを使用 |
| 22 | = | ( a b -- flag ) | |
| 23 | SLIT | ( -- n ) | 次のスロット、符号付き（−16〜+15）。規則② |
| 24 | < | ( a b -- flag ) | 符号付き |
| 25 | U< | ( a b -- flag ) | 符号なし |
| 26 | @ | ( addr -- x ) | 32bit |
| 27 | ! | ( x addr -- ) | 32bit |
| 28 | C@ | ( addr -- c ) | 8bit、ゼロ拡張 |
| 29 | C! | ( c addr -- ) | 8bit |
| 30 | UA | ( -- UP+n×4 ) | nは次のスロット（0〜31）。規則② |

- 戻り番地（ret）は次の語のバイトアドレス。CALL・EXECが積む戻り番地の下位2bitは0。
- RETで取り出した値の下位2bitが0でなければ例外10（アドレスの境界違反）。戻り番地のbit0（モード）を解釈するのはRETIだけ。
- 普通の32bit乗算は `UM* DROP`。

### 5.1 乗算・除算の仕様

| 項目 | 仕様 |
|---|---|
| UM* | 符号なし。DSP（18×18を4個）で2段に分けて実行 |
| M* | 符号付き（上位32bitが符号付きの結果になる） |
| 除算器 | ロジックで作る反復型（1bit/サイクル、32サイクル）。1コアに1個、スレッド間で共有 |
| 実行中 | 除算を発行したスレッドだけを待機させ、他のスレッドは実行を続ける |
| 除算器が使用中 | 別のスレッドが除算を発行したら、除算器が空くまで待機させる。待ちの順番は発行した順 |
| 丸め | 0方向への切り捨て（C言語、RISC-Vと同じ） |
| 0除算 | 例外にしない。商＝0xFFFF_FFFF、余り＝被除数 |
| /MODの −2³¹ ÷ −1 | 商＝−2³¹、余り＝0 |
| UM/MODで商があふれる（hi ≥ u） | 商＝0xFFFF_FFFF、余り＝不定（シミュレータでは0）。例外にしない。u＝0もこれにあたる（0除算の規則より優先） |

### 5.2 拡張命令

| 項目 | 内容 |
|---|---|
| 対象 | M*、U/MOD、/MOD、UM/MOD（今後追加する、ハードウェアにない場合がある命令も同じ扱い） |
| 置き場所 | 語の最後のスロット |
| ハードウェアにない場合 | そのスロットまで実行してから例外18（未実装命令）。戻り先は次の語 |
| ハンドラ | ブートROMに置く。オペランドはユーザーのデータスタックにそのまま載っているので、普通のサブルーチンとして処理してRETIで戻る |
| 申告 | CSRのFEATURES |

## 6. スレッドとバレル実行

### 6.1 スケジューリング

- 実行可能なスレッドだけでラウンドロビンする（方式1）。
- 順番はtidの小さい順。前に発行したスレッドの次から、実行可能なスレッドを探す。リセット直後はスレッド0から探す。
- 20K（2コア）のシミュレーションでは、1サイクルごとにコア0、コア1の順に1回ずつ進める。
- 同じスレッドの命令は**D（＝4）サイクル以上あけて**発行する。実行可能なスレッドがDより少ないときは空サイクルを入れる。これによりハザード処理（フォワーディング、インターロック、分岐予測）は不要。
- 時間のかかる操作（除算、外部RAMへのアクセス、SENDMのブロック、RECV・WAITの待ち）の間は、そのスレッドだけを待機状態にする。
- 1回の番で1命令を実行する。オペランド用のスロット（SLIT・UA・SYSのオペランド、CSR@・CSR!・SENDM・SENDM?の即値）は命令と同じ番で読み、番を使わない。
- 埋め草のNOPも1命令として1回の番を使う（NOPを飛ばさない）。
- 語の途中でブロックしても、命令語バッファとスロット番号が残るので、再開すると続きのスロットから実行される。

### 6.2 スレッドごとの状態

| 状態 | 幅 | 備考 |
|---|---|---|
| PC | 22〜30bit | |
| 命令語バッファ・スロット番号 | 32bit＋3bit | |
| T、N | 32bit×2 | データスタックの一番上（T）と2番目（N）。残りはスタック用RAM |
| データスタック・リターンスタック | 32bit×16〜32段 ずつ | BSRAMに置く（9K） |
| DSP、RSP | 各5〜10bit | |
| UP | 32bit（下位7bitは常に0） | |
| モードビット | 1bit | 1＝特権 |
| イベントのラッチ | 32bit | |
| スレッドごとのCSR | | 8章 |
| タイマの比較レジスタ | 64bit | 12.5節 |

### 6.2.1 スタックの深さとSP・RP

| 項目 | 規則 |
|---|---|
| 深さの数え方 | TとNを含めた要素の総数（0〜容量） |
| データスタックの容量 | STACKDEPTH。これを超えるとオーバーフロー（例外0）、0未満でアンダーフロー（例外1） |
| リターンスタックの容量 | STACKDEPTH−3（最後の3段はレッドゾーン）。これを超えるとオーバーフロー（例外2）、0未満でアンダーフロー（例外3） |
| 例外の入口 | レッドゾーンを使ってリターンスタックに積む（オーバーフローの判定の対象外） |
| SP・RPの値 | 現在の深さ（要素の数）。SP@・RP@は、命令を実行する直前の深さを積む |
| SP!・RP! | 深さを設定する。増やした分の中身は不定（シミュレータでは、スタック用RAMに残っている以前の値。書いたことのない段は0） |
| SP!・RP!の範囲外の値 | SP!・RP!自体は例外にしない。容量を超える値や負の値を設定した場合は、次の語のフェッチ時の判定でオーバーフロー・アンダーフローの例外になる |
| 判定の時点 | 語のフェッチ時に、6スロット分の増減を累積した最大値・最小値で判定する（7.1節） |

### 6.3 tidの形式（8bit）

```
 7      4 3      0
+--------+--------+
|コア番号 |スレッド番号|
+--------+--------+
```
カーネル（コア0・スレッド0）のtidは0。存在しないtidへのSENDM・SIGNALは例外14。

### 6.4 イベントとWAIT

| ビット | イベント | 種類 |
|---|---|---|
| 0 | メールボックス着信 | 状態（FIFOが空でない） |
| 1 | SIGNAL | ラッチ |
| 2 | タイマ（自分の比較レジスタ） | ラッチ |
| 3 | VSYNC | ラッチ |
| 4 | UART受信データあり | 状態 |
| 5 | UART送信FIFOに空きあり | 状態 |
| 6〜15 | 予約（キーボード、マウス、記憶装置、音声など） | |
| 16〜31 | 予約 | |

- ラッチ式のビットは、立ったまま残る。WAITは、ビットが立っていればすぐに戻り、そのビットを消す（起こし忘れを防ぐ）。
- デバイスのイベントは全スレッドのラッチに同時に立てる。ラッチはスレッドごとに独立。
- maskが0のWAITは、そのスレッドの停止として扱う。再開はTHREADCTLによるリセットだけ（HALTと同じ）。
- ジョイパッドはイベントにしない（VSYNCを待ってから読む）。

## 7. 例外

### 7.1 基本方針（案B）

- 割り込み・例外・戻りは、すべて**語の切れ目**で扱う。
- 再開が必要な例外は、すべて**語を実行する前（フェッチ時）**に判定できる。
- スタックのあふれは、フェッチ時に6スロット分の深さの増減を累積し、語の途中での最大値・最小値で判定する。命令ごとの増減は命令の種類だけで決まる。
- 拡張命令の未実装（例外18）とSYSCALLは語の最後に置くので、そのスロットで起こしても戻り先は次の語。
- 値によって決まる実行時の例外は、プログラムの誤りとして扱い、再開しない。
- 非同期の割り込みは使わない（デバイスはイベント、時間はタイマのイベント）。

### 7.2 例外番号

| 番号 | 例外 | 検出の時点 | 再開 |
|---|---|---|---|
| 0 | データスタックのオーバーフロー | フェッチ時 | ○（語の先頭から） |
| 1 | データスタックのアンダーフロー | フェッチ時 | ○ |
| 2 | リターンスタックのオーバーフロー | フェッチ時 | ○ |
| 3 | リターンスタックのアンダーフロー | フェッチ時 | ○ |
| 4 | 不正命令（未定義の命令、SYSの予備番号、存在しないCSR） | フェッチ時 | × |
| 5 | 配置違反 | フェッチ時 | × |
| 6 | 特権違反（命令） | フェッチ時 | ○（エミュレーションする場合） |
| 7 | 命令フェッチ違反（実行できない場所からのフェッチ） | フェッチ時 | × |
| 8 | SYSCALL | そのスロット | ○（次の語へ） |
| 9 | ブレークポイント（BRK） | フェッチ時 | ○ |
| 10 | アドレスの境界違反（UP!の128バイト境界を含む） | 実行時 | × |
| 11 | バスエラー（割り当てのない番地。0x0000_0000〜0x000F_FFFFを含む） | 実行時 | × |
| 12 | 保護違反（ROMへの書き込み、ユーザーページの読み出し専用レジスタへの書き込みを含む） | 実行時 | × |
| 13 | リモートXCHG違反 | 実行時 | × |
| 14 | 不正なスレッド番号 | 実行時 | × |
| 15 | 二重例外 | — | ×（ハードウェアでスレッドを停止） |
| 16 | 予約（データのページフォールト） | — | — |
| 17 | 予約（命令のページフォールト） | — | — |
| 18 | 未実装命令（拡張命令がハードウェアにない） | そのスロット | ○（次の語へ） |

### 7.3 入口と出口

- **入口**：戻り先（語のバイトアドレス）のbit0に現在のモードを入れて、リターンスタックに積む（1段）。特権モードにして、VBR＋番号×4へ飛ぶ。ECAUSE、EPC、EIR、ESLOT、EADDRを記録する。
- **戻り先のbit1**：拡張形式（案A、仮想記憶用）のフラグとして予約。現在は常に0。
- **出口**：RETIで戻り先とモードを戻す。
- リターンスタックの最後の3段はレッドゾーンとして予約し、そこに達したら例外2を起こす（将来の拡張形式に備える）。
- ハンドラは、積まれた値を直接読まず、RETIで戻るかCSRを読む（形式が変わっても影響を受けないため）。

### 7.4 再開しない例外の扱い

1. ベクタ先のハンドラがCSRを読み、カーネルにFAULT（10.4節）を送ってスレッドを停止する。
2. カーネル自身（tid 0）の例外は、ROMのモニタに入ってUARTに状態を表示する。
3. 二重例外では、ハードウェアがスレッドを止め、LEDやUARTでデバッグ用の表示を出す。

## 9. メモリマップと保護

### 9.1 メモリマップ（単一アドレス空間、エイリアスなし）

| アドレス | 内容 |
|---|---|
| 0x0000_0000 – 0x000F_FFFF | 割り当てなし（バスエラー。ヌルポインタの検出） |
| 0x0010_0000 – | コア0のローカルBSRAM（窓は64KB） |
| 0x0011_0000 – | コア1のローカルBSRAM（窓は64KB） |
| 0x0100_0000 – 0x017F_FFFF | 外部RAM（8MB） |
| 0xFF00_0000 – 0xFFFE_FFFF | I/O（12.1節） |
| 0xFFFF_0000 – 0xFFFF_0FFF | ブートROM（4KB、全コアで共有） |

### 9.2 アクセスの規則

| アクセス | 速さ | 仕組み |
|---|---|---|
| 自コアのローカルBSRAM | 1サイクル | BSRAMのポートA |
| 他コアのローカルBSRAM | 数サイクル（シミュレータでは2サイクル） | 相手のBSRAMのポートB。相手のパイプラインは止まらない |
| 外部RAM | 数〜十数サイクル（シミュレータでは8サイクル） | アービタ経由。表示回路を最優先 |
| 命令フェッチ | — | **自コアのローカルBSRAMとブートROMからのみ**（A3①）。それ以外は例外7（自コアのローカルBSRAMの窓のうち、容量の外を含む） |

- ブートROMへの書き込みは例外12。
- シミュレータの待ち時間（外部RAM 8サイクル、他コアのローカルBSRAM 2サイクル）は固定値で、構成で変えられる。
- ローカルBSRAMの窓（64KB）のうち、実装した容量（LOCALSIZE）より後ろはバスエラー（例外11）。
- ローカルBSRAMの初期値は、シミュレータでは0（実機では不定。ソフトは0を前提にしない）。
- I/Oへの8bitアクセス（`C@`・`C!`）は、テキストVRAM、フォントRAM、保護キー表でだけ使える。それ以外のI/Oレジスタへの8bitアクセスは例外10。
- 他コアのローカルBSRAMに対するXCHGは例外13。複数のコアで共有するロックは外部RAMに置く（アービタでアトミックにする）。
- ローカルBSRAMへのXCHGは、BSRAMの「書き込み前の値を出力する」モードを使い、1サイクルで行う。
- キャッシュなし・インオーダーなので、メモリ順序は逐次一貫性。FENCEは将来のために残す。
- 共有モジュールは、コアごとのローカルBSRAMに1つずつコピーを置く（命令は自コアのローカルからしか実行できないため）。

### 9.3 リロケータブルとリエントラント

| 仕組み | 内容 |
|---|---|
| PC相対分岐 | 3.3節 |
| PCREL | モジュール内のデータのアドレスを得る。モジュール内のアドレスはLITで埋め込まない |
| 他モジュールの呼び出し | LINKで入口のアドレスを得て、EXECで呼ぶ |
| UP | スレッドごとのユーザー領域。128バイト境界。UAは `UP OR (n<<2)` で計算する（加算器が不要） |

ユーザー領域の配置（案）：

| n | 内容 |
|---|---|
| 0 | 退避したデータスタックポインタ |
| 1 | 退避したリターンスタックポインタ |
| 2 | タスク番号 |
| 3 | エラーコード |
| 4 | 数値の基数（BASE） |
| 5 | 標準入力のデバイス |
| 6 | 標準出力のデバイス |
| 7〜31 | アプリケーション用 |

### 9.4 メモリ保護（ページキー方式）

| 項目 | 内容 |
|---|---|
| ページの大きさ | 外部RAM：4KB（2,048ページ）、ローカルBSRAM：1KB |
| 表の1項目（8bit） | キー（5bit、0〜31）＋W（書き込み可）＋X（実行可）＋予備1bit |
| 外部RAMの表 | BSRAM 1ブロック。20Kではデュアルポートで2コアが共有 |
| ローカルBSRAMの表 | コアごとの小さな表 |
| 表の置き場所 | I/Oの0xFF08_0000（特権モードのみ） |
| リセット直後 | 全ページがキー0 |

判定の規則（一般モードのみ。特権モードは検査しない）：

| アクセス | 許可の条件 |
|---|---|
| 読み出し | PKREAD[ページのキー]＝1 |
| 実行 | PKREAD[ページのキー]＝1 かつ X＝1 |
| 書き込み | PKWRITE[ページのキー]＝1 かつ W＝1 |

キーの使い方（例）：

| キー | 用途 | ページの設定 |
|---|---|---|
| 0 | カーネル | 特権モード専用 |
| 1 | 公開の共有モジュール | X＝1、W＝0 |
| 2〜 | 特定のプロセスだけが使う共有モジュール、各プロセスのデータ | コードはX＝1・W＝0、データはX＝0・W＝1 |

- バッファの所有権を渡すときは、ページのキーを相手のキーに書き換える（GRANT）。単一アドレス空間なので、ポインタはそのまま有効。
- I/O領域は、ユーザーページを除いて一般モードからアクセスできない（例外12）。
- 同時に保護できるプロセスは31個（キー0はカーネル）。

## 10. スレッド間通信

### 10.1 メールボックス

| 項目 | 仕様 |
|---|---|
| 置き場所 | 1コアにBSRAM 1ブロック（512語）を、スレッド数で等分 |
| 順序 | 同じ送信元から同じ相手へのメッセージは、送った順に届く |
| 用途 | 通知と場所（ポインタ）を送る。大きなデータは共有メモリに置く |

### 10.2 命令

| 命令 | 動作 |
|---|---|
| SENDM #n | 相手のFIFOにn＋1語の空きができるまで待ち、ヘッダとn語を途切れずにまとめて送る |
| SENDM? #n | 空きがなければ送らずに偽を返す。成否にかかわらず引数を消費する |
| RECV | 1語ずつ受け取る。先にヘッダを読み、語数分だけ続けて読む |

nを即値にしているのは、フェッチ時のスタック深さ判定で増減（−(n＋2)）を決められるようにするため。

- 同じ相手に複数のスレッドがSENDMで待っているときは、空きができたら待ち始めた順に送る。
- 自分自身へのSENDMも許す（FIFOが一杯なら永久に待つが、それはプログラムの誤り）。

### 10.3 ヘッダ

```
 31      24 23            8 7    4 3    0
+----------+---------------+------+------+
| 送信元tid | tag（16bit）  | 予備 |  n   |
+----------+---------------+------+------+
  ハードウェア  送信側が指定    0    ハードウェア
```
送信元のtidはハードウェアが書き込むので偽れない。

### 10.4 tag

```
 15      8 7       0
+---------+---------+
|  分類   |  依頼   |
+---------+---------+
  bit15＝1：返事
```

| 分類 | 内容 |
|---|---|
| 0x00 | システム |
| 0x01 | コンソール（画面とキーボード） |
| 0x02 | メモリ |
| 0x03 | タスク |
| 0x04 | モジュール |
| 0x05〜0x6F | 予約（記憶装置、音声など） |
| 0x70〜0x7F | アプリどうしで自由に使う |
| 0x80〜0xFF | 返事（bit15＝1） |

| tag | 名前 | 内容（最大4語） | 返事の内容 |
|---|---|---|---|
| 0x0001 | START | UP、PC（bit0＝モード）、PKREAD、PKWRITE | なし |
| 0x0002 | EXITED | 終了コード | なし |
| 0x0003 | FAULT | 例外番号、EPC、EADDR | なし |
| 0x0101 | PUTC | 文字 | 状態 |
| 0x0102 | PUTS | 文字列のポインタ、長さ | 状態 |
| 0x0103 | GETC | なし | 状態、文字 |
| 0x0104 | LOCATE | 桁、行 | 状態 |
| 0x0105 | COLOR | 属性 | 状態 |
| 0x0106 | CLS | なし | 状態 |
| 0x0107 | DEFCHAR | 文字コード、16バイトのデータへのポインタ | 状態 |
| 0x0201 | ALLOC | サイズ | 状態、ポインタ |
| 0x0202 | FREE | ポインタ | 状態 |
| 0x0203 | GRANT | ポインタ、長さ、相手のtid | 状態 |
| 0x0301 | SPAWN | 起動情報のブロックへのポインタ | 状態、tid |
| 0x0302 | KILL | tid | 状態 |
| 0x0303 | WAITEXIT | tid | 状態、終了コード |
| 0x0401 | LINK | モジュール名へのポインタ | 状態、入口のアドレス |

- 返事のtagは、依頼のtagのbit15を1にしたもの（例：ALLOCの返事は0x8201）。
- 返事の最初の1語は状態。
- 4語に収まらない依頼は、内容をメモリに書いてポインタを送る。

| エラーコード | 意味 |
|---|---|
| 0 | 成功 |
| −1 | 不明な依頼 |
| −2 | 引数が不正 |
| −3 | メモリ不足 |
| −4 | 見つからない |
| −5 | 権限がない |
| −6 | 使用中 |

### 10.5 デッドロックを防ぐ規則

- クライアントは、依頼を送ったら返事を受け取るまで次の依頼を送らない（そのため依頼の識別番号は不要）。
- カーネルとドライバは、返事にSENDM?を使い、送れなかった内容はメモリに保持して後で再送する。

## 11. 起動とスレッドの制御

### 11.1 リセット時の状態

| 状態 | 値 |
|---|---|
| PC | 0xFFFF_0000（全スレッド共通） |
| モード | 特権 |
| DSP、RSP | 0（空） |
| UP | 0 |
| VBR | 0xFFFF_0100 |
| 保護キー表 | 全ページがキー0 |

全スレッドが同時に同じ番地から実行を始める。

### 11.2 起動の流れ

```forth
\ 0xFFFF_0000
TID 0= IF  boot  ELSE  idle  THEN
```

- **boot（tid 0のみ）**：UARTに起動メッセージを出し、外部RAMを確認する。OSのコードをローカルBSRAMへ、データを外部RAMへ読み込み、VBRなどを設定してOSの入口へ飛ぶ。tid 0はそのままカーネルスレッドになる。OSイメージの読み込み元（QSPIフラッシュをユーザー回路から読めるか）は要確認。
- **idle（その他のスレッド）**：起動依頼を待つ。
- **シミュレータ**：QSPIフラッシュからの読み込みの代わりに、イメージファイルをローカルBSRAM（または外部RAM）に直接読み込む機能を持つ。
- **外部RAMの初期値**：シミュレータでは0。実機では不定なので、ソフトは0を前提にしない。

### 11.3 idleループ

```forth
: idle
   BEGIN
     スタックを空にする（SP!  RP!）
     RECV                                    \ ヘッダ
     送信元がtid 0 かつ tag＝START か？
     IF   RECV UP!  RECV >R                  \ UPを設定、PC（bit0＝モード）を退避
          RECV PKREAD CSR!  RECV PKWRITE CSR!
          RETI                               \ 指定のモードでPCへ
     ELSE ヘッダのn語分をRECVして捨てる
     THEN
   AGAIN ;
```

- 一般モードへの切り替えは、PCのbit0を0にしてリターンスタックに積み、RETIで行う。
- カーネル以外からのSTARTは無視する（送信元はハードウェアが書き込むので偽れない）。

### 11.4 SYSCALL

| 番号 | 名前 | スタック効果 | 内容 |
|---|---|---|---|
| 0 | EXIT | ( code -- ) | タスクを終了する。カーネルにEXITEDを送り、スタックを空にしてidleループへ戻る |
| 1 | DPUTC | ( c -- ) | デバッグ用。UARTに1文字を直接出力 |
| 2 | DGETC | ( -- c ) | デバッグ用。UARTから1文字を直接受け取る |
| 3 | MONITOR | ( -- ) | ROMのモニタに入る |
| 4〜 | — | — | 予約 |

OSの機能はメッセージで依頼する。SYSCALLはメッセージでは扱えないものだけ。

### 11.5 スレッドの強制停止

| アドレス | 名前 | 内容（特権モードのみ） |
|---|---|---|
| 0xFF00_4000 | THREADCTL | tidを書き込むと、そのスレッドをリセット状態にする（idleループに戻る） |
| 0xFF00_4100＋tid×4 | THREADSTAT[tid] | 各スレッドの状態（12.7.5節） |

### 12.2 画面

#### 画面モード

| モード | 内容 | 機種 | 状況 |
|---|---|---|---|
| 0 | テキスト80×30（640×480出力） | 全機種（保証） | **最初に実装** |
| 1 | フレームバッファ 320×240（640×480に2倍で出力） | 9K以上 | 将来 |
| 2 | タイル＋スプライト | 20K（9Kは条件付き） | 将来 |
| 3 | フレームバッファ 1280×720（720p出力） | 20K以上 | 将来 |

- どのモードを入れるかは合成時に決める。ソフトは読み出し専用のVIDCAPSで確認する（bit0＝モード0で常に1、bit1〜3＝モード1〜3）。
- 使えないモードを選んだ場合は切り替えず、エラーのビットを立てる。
- モードは同時に1つ（排他）。テキストの重ね合わせをオプションにするかは未決定。
- 16:9のモニタでは、640×480出力の表示比率はモニタの設定に依存する。

#### モード0の仕様

| 項目 | 仕様 |
|---|---|
| 出力 | 640×480・60Hz、ピクセルクロック25.2MHz（27MHzからPLLで生成） |
| 文字数 | 80×30、1文字8×16ドット |
| 色 | 16色パレット（各色RGB各8bit） |
| テキストVRAM | 文字n番（n＝行×80＋桁）：+2nに文字コード、+2n+1に属性。4,800バイト、デュアルポートBSRAM |
| 属性 | 下位4bit＝文字色、上位4bit＝背景色 |
| フォントRAM | 文字コードcのr行目：+c×16+r。bit7が左端（1＝文字色）。256文字×16バイト＝4KB。CPUからいつでも書き換えでき、即時に反映 |
| フォントの初期値 | 0x20〜0x7EはASCII。0x00〜0x1F、0x7F、0x80〜0xFFは空白 |
| 文字コードの解釈 | ハードウェアは図柄を表示するだけ。改行などの制御はOSのコンソールドライバが行う |

制御レジスタ：

| レジスタ | 内容 |
|---|---|
| VIDCAPS | 使えるモード（読み出しのみ） |
| VIDMODE | 画面モードの選択 |
| CTRL | 表示の有効化 |
| CURSOR | カーソルの桁・行 |
| CURSORCTL | カーソルの表示、点滅、形（開始ラインと終了ライン） |
| SCROLL | 画面の先頭に表示する行（0〜29）。VRAMを30行の輪として扱う |
| PALETTE[0〜15] | パレット |
| STATUS | 垂直帰線期間中かどうか |

- イベント：VSYNC（ビット3）。
- VRAMとフォントRAMは特権モードのみ。アプリはコンソールのドライバにメッセージで依頼する。

#### モード1・3（フレームバッファ）の方針

- フレームバッファは外部RAMに置き、表示回路が1ライン分ずつBSRAMのラインバッファに読み込んで表示する。
- 色数は8bpp（256色パレット）を想定（未確定）。モード1は75KB、モード3は約900KB。
- フレームバッファの先頭番地をレジスタで指定する（ダブルバッファに使える）。

### 12.3 UART

| 項目 | 仕様 |
|---|---|
| 接続 | 基板のUSBシリアル（9KはBL702、20KはBL616） |
| 通信速度 | 115,200bps、8N1（分周比で変更可能） |
| FIFO | 送信・受信とも16バイト |
| レジスタ | DATA（書くと送信、読むと受信）、STATUS、DIV |
| イベント | ビット4（受信データあり）、ビット5（送信FIFOに空きあり） |
| 用途 | デバッグと、当初のキーボード代わり。OSの出力はHDMIとUARTの両方に出せる |

### 12.4 GPIO

| 項目 | 仕様 |
|---|---|
| ジョイパッド | 2つ、各8ボタン（16ピン）。ボタンの一方をピン、もう一方をGND（内部プルアップ） |
| チャタリング除去 | ハードウェアで行う |
| JOYレジスタ | bit7〜0＝JOY0、bit15〜8＝JOY1。押されていれば1 |
| ボタンのビット | 0＝上、1＝下、2＝左、3＝右、4＝A、5＝B、6＝SELECT、7＝START |
| LED | 基板のLED（6個）の出力レジスタ |
| イベント | なし |

ピンの割り当ては、20Kの空きピンを確認したうえで決める（9Kは汎用I/Oが45本あるので足りる）。

### 12.5 タイマ

| 項目 | 仕様 |
|---|---|
| カウンタ | 64bitのフリーランカウンタ。**1マイクロ秒で固定**（CPUのクロックに依存しない） |
| 比較レジスタ | スレッドごとに1つ（64bit） |
| 動作 | CMP_HI、CMP_LOの順に書くと比較を開始。カウンタが比較値以上になるとイベント2を立てて比較を止める |
| 64bitの読み出し | 上位→下位→上位の順に読み、上位が変わっていなければ確定（保持の仕組みは持たない） |

### 12.6 ユーザーページ（0xFF0F_0000〜0xFF0F_0FFF）

| オフセット | 名前 | アクセス | 内容 |
|---|---|---|---|
| +0x000 | CNT_LO | 読み出しのみ | タイマのカウンタ（下位） |
| +0x004 | CNT_HI | 読み出しのみ | タイマのカウンタ（上位） |
| +0x008 | CMP_LO | 読み書き | 自分の比較レジスタ（下位）。書くと比較を開始 |
| +0x00C | CMP_HI | 読み書き | 自分の比較レジスタ（上位） |
| +0x010 | JOY | 読み出しのみ | ジョイパッド |
| +0x014〜 | （予約） | — | バスエラー。+0x014はフレームカウンタの候補 |

- 「自分の」比較レジスタは、アクセスしたスレッドのtidで回路が選ぶ。
- 読み出し専用のレジスタへの書き込みは例外12。

### 12.7 I/Oレジスタのオフセット

特記のないレジスタは32bit。読み出し専用のレジスタへの書き込みと、書き込み専用のレジスタからの読み出しは例外12。割り当てのないオフセットはバスエラー（例外11）。

#### 12.7.1 UART（0xFF00_0000）

| オフセット | 名前 | アクセス | 内容 |
|---|---|---|---|
| +0x00 | DATA | 読み書き | 書く：下位8bitを送信FIFOへ（一杯なら捨てる）。読む：下位8bitが受信データ、bit31＝1なら受信データなし |
| +0x04 | STATUS | 読み出し（bit3のみ1を書くと消える） | bit0＝受信データあり、bit1＝送信FIFOが一杯、bit2＝送信がすべて完了、bit3＝受信あふれ |
| +0x08 | DIV | 読み書き | 分周比＝クロック÷通信速度。リセット値は115,200bps相当 |

#### 12.7.2 タイマ（0xFF00_1000、特権モードのみ）

| オフセット | 名前 | アクセス | 内容 |
|---|---|---|---|
| +0x000 | CNT_LO | 読み出しのみ | カウンタ（下位） |
| +0x004 | CNT_HI | 読み出しのみ | カウンタ（上位） |
| +0x008 | PRESCALE | 読み出しのみ | 1マイクロ秒あたりのクロック数 |
| +0x800＋tid×8 | CMP_LO[tid] | 読み書き | 各スレッドの比較レジスタ（下位）。書くと比較を開始 |
| +0x804＋tid×8 | CMP_HI[tid] | 読み書き | 同上（上位） |

#### 12.7.3 GPIO（0xFF00_2000）

| オフセット | 名前 | アクセス | 内容 |
|---|---|---|---|
| +0x00 | JOY | 読み出しのみ | bit7〜0＝JOY0、bit15〜8＝JOY1 |
| +0x04 | LED | 読み書き | bit5〜0＝基板のLED（1＝点灯） |

#### 12.7.4 画面の制御（0xFF00_3000）

| オフセット | 名前 | アクセス | 内容 |
|---|---|---|---|
| +0x00 | VIDCAPS | 読み出しのみ | bit0〜3＝モード0〜3が使えるか |
| +0x04 | VIDMODE | 読み書き | bit1〜0＝モード。bit31＝エラー（使えないモードを指定した。読み出しのみ、次に正しいモードを書くと消える） |
| +0x08 | CTRL | 読み書き | bit0＝表示の有効化（リセット値1） |
| +0x0C | STATUS | 読み出しのみ | bit0＝垂直帰線期間中 |
| +0x10 | CURSOR | 読み書き | bit6〜0＝桁（0〜79）、bit12〜8＝行（0〜29） |
| +0x14 | CURSORCTL | 読み書き | bit0＝表示、bit1＝点滅、bit11〜8＝開始ライン、bit15〜12＝終了ライン |
| +0x18 | SCROLL | 読み書き | 画面の先頭に表示する行（0〜29） |
| +0x40〜+0x7C | PALETTE[0〜15] | 読み書き | bit23〜16＝R、bit15〜8＝G、bit7〜0＝B |
| +0x100〜 | （予約） | | モード1〜3用 |

パレットのリセット値は未決定（シミュレータでは一般的な16色を仮に使う）。

#### 12.7.5 スレッドの制御（0xFF00_4000、特権モードのみ）

| オフセット | 名前 | アクセス | 内容 |
|---|---|---|---|
| +0x000 | THREADCTL | 書き込みのみ | tidを書くと、そのスレッドをリセット状態にする |
| +0x100＋tid×4 | THREADSTAT[tid] | 読み出しのみ | 0＝リセット直後、1＝実行中、2＝WAIT中、3＝RECV待ち、4＝SENDで待機中、5＝除算・メモリ待ち、6＝HALT、7＝二重例外で停止 |

#### 12.7.6 保護キー表（0xFF08_0000、特権モードのみ）

| オフセット | 内容 |
|---|---|
| +0x0000〜+0x07FF | 外部RAMのページ0〜2047（1ページ1バイト） |
| +0x1000＋コア番号×0x100 | 各コアのローカルBSRAMのページ（1KB単位、最大64項目） |

1項目（1バイト）：bit4〜0＝キー、bit5＝W、bit6＝X、bit7＝予約。C!で1ページずつ、!（32bit）で4ページ分をまとめて書ける。

## 13. ソフトウェアの規約

### 13.1 互換性のための約束

| 約束 | 理由 |
|---|---|
| アプリは2.3節の最小保証値の範囲で動くように書く | 機種によって構成が違う |
| 構成はCSR（NCORES、NTHREADS、FEATURESなど）とVIDCAPSで調べる | 同上 |
| 時間は必ずタイマで測る。命令の実行時間に頼らない | 機種ごとにクロックとスレッド数が違う |
| 拡張命令は語の最後に置く | ない機種ではソフトで代わりに実行するため |
| 自分がローカルBSRAMにあることを前提にしない | 将来の4Kでは外部RAMに置かれる |
| リターンスタックの段数を固定値で決めつけない | レッドゾーンの段数が変わる可能性がある |

### 13.2 アセンブラの規則

- スロットへの自動詰め込み。
- 分岐が届かない場合は、残りのスロットをNOPで埋めて次の語に移す。
- 配置の規則（3.4節）を検査する。
- モジュール内のアドレスは必ずPCRELで得る（LITで埋め込まない）。
- EXEC、SYSCALL、拡張命令の後ろのスロットはNOPで埋める。

### 13.3 ニーモニックの別名表（レジスタ風）

アセンブラは、Forth風とレジスタ風の両方の名前を受け付ける（命令の実体は同じ）。逆アセンブラはどちらの表記でも出力できる。

考え方：T（一番上）を暗黙のアキュムレータ、N（2番目）を第2オペランドとみなす。2項演算は `T ← N 演算 T` で結果を1つ残す。

| 番号 | Forth風 | レジスタ風 | 動作 |

| 0 | NOP | NOP | 何もしない |
| 1 | LIT n | PUSH #n | 定数を積む |
| 2 | JMP | BRA label | 分岐 |
| 3 | JZ | BZ label | Tを取り出し、0なら分岐 |
| 4 | CALL | BSR label | サブルーチン呼び出し |
| 5 | RET | RTS | 復帰 |
| 6 | EXEC | JSR (T) | Tのアドレスを呼び出す |
| 7 | >R | PSHR | Tをリターンスタックへ移す |
| 8 | R> | PULR | リターンスタックから戻す |
| 9 | R@ | PEEKR | リターンスタックの先頭を複写して積む |
| 10 | DUP | PUSH T | Tを複写して積む |
| 11 | DROP | POP | Tを捨てる |
| 12 | SWAP | EXG | TとNを交換 |
| 13 | OVER | PUSH N | Nを複写して積む |
| 14 | + | ADD | T ← N＋T |
| 15 | - | SUB | T ← N−T |
| 16 | AND | AND | |
| 17 | OR | OR | |
| 18 | XOR | EOR | |
| 19 | LSHIFT | LSL | T ← N を T ビット左シフト |
| 20 | RSHIFT | LSR | T ← N を T ビット論理右シフト |
| 21 | UM* | MULU | 符号なし乗算（下位・上位） |
| 22 | = | CMPEQ | N＝Tなら−1 |
| 23 | SLIT n | PUSHQ #n | 小さい定数（−16〜+15） |
| 24 | < | CMPLT | N＜T（符号付き）なら−1 |
| 25 | U< | CMPLO | N＜T（符号なし）なら−1 |
| 26 | @ | LD | T ← [T]（32bit） |
| 27 | ! | ST | [T] ← N（32bit） |
| 28 | C@ | LDB | T ← [T]（8bit） |
| 29 | C! | STB | [T] ← N（8bit） |
| 30 | UA n | LEA n,U | U＋n×4を積む |

| SYS番号 | Forth風 | レジスタ風 |
|---|---|---|
| 0 | TID | TID |
| 1 | WAIT | WAIT |
| 2 | SIGNAL | SIGNAL |
| 3 | SENDM #n | SEND n |
| 4 | RECV | RECV |

### 13.4 その他

- 複数のコアで共有するロックは外部RAMに置く。
- ドライバは物理アドレスを直接書かず、デバイスの番地はカーネルから受け取る。
- 呼び出し規約（引数と戻り値、1つの関数が使ってよいスタックの深さ）は未決定。

### 14.3 実装の進め方

**モード0（CPUなしで始める）**

1. PLL、640×480のタイミング生成、TMDSエンコーダ、シリアライザ（カラーバー）

5. CPUのバスにつなぐ

**ツール（JavaScript、HTML/CSSのグラフィカルなシミュレータ）**

1. アセンブラ（命令の符号化、スロットへの詰め込み、配置規則の検査、マクロ）
2. 1スレッドの命令実行（基本命令とSYS拡張）
3. バレル（複数スレッド）、イベント、WAIT、メールボックス
4. 例外、スタック深さの判定、保護キー
5. 周辺回路（UART、タイマ、ジョイパッド、テキスト画面）
6. ブートROM（起動メッセージ、idleループ）と、サンプルプログラムでの動作確認

シミュレータの方針：命令単位で実行し、バレルのスレッド切り替えの順番はRTLと同じにする。時間は仮想時間（実行したサイクル数からマイクロ秒を計算）で、毎回同じ結果になるようにする。仮想時間の計算に使うクロックは、9Kで54MHz、20Kで72MHz（構成で変えられる）。

**CPU（RTL）**

1. 1スレッドのコア（シミュレータと結果を比較）
2. バレル化（8スレッド）、イベント、WAIT
3. メールボックスとSENDM・RECV（idleループとSTARTで確認）
4. 例外、スタック深さの判定、保護キー
5. タイマ、GPIO
6. 外部RAMのコントローラ（9KはPSRAM、20KはSDRAM）
7. 20Kでの2コア化
8. 乗算・除算器

UART経由でスレッドを止め、1語ずつ実行し、状態を読み出すデバッグ機能を、CPUの段階1〜2で入れる。
