## 段階4　例外、スタック深さの判定、保護キー

- [x] **T-30　フェッチ時の例外での ESLOT・EADDR の値**
  案：ESLOT＝原因の命令のスロット（スタックのあふれは、あふれたスロット）。EADDR＝アドレスに関係しない例外では0。

- [x] **T-31　二重例外（例外15）の条件**
  案：例外の入口の処理中（リターンスタックのレッドゾーンを使い切った、VBRの先のフェッチで例外になった）に、さらに例外が起きたとき。

- [x] **T-32　同じ語で複数の例外の条件が成り立つときの優先順位**

  決定：案のとおり。2026-11-14
- [x] **T-33　PKREAD・PKWRITEのビットの意味**
  案：ビットn＝キーnを使えるか（32bitで31個のキー＋キー0）。
  決定：案のとおり。2026-11-14
- [x] **T-34　ブートROMのページの権限（仕様書14.1節）**
  一般モードから読み出し・実行できるか。
  案：読み出し・実行ともに不可（ハンドラは特権モードで動く）。
  決定：案のとおり。2026-11-14

- [x] **T-88　実行の権限がないページからの命令フェッチ（一般モード）の例外番号**（段階4の実装で生じた項目）
  ページのキーがPKREADにない、またはX＝0のページからのフェッチ。例外7（実行できない場所からのフェッチ）か例外12（保護違反）か。
  案：例外12（例外7は「そもそもフェッチできない領域」に限る。ブートROMを一般モードで実行したときを例外12とした9.4節とも合う）。現在の実装はこの案。
  決定：案のとおり（例外12）。2026-11-14
- [x] **T-89　リターンスタックの深さが負（RP!で設定）のときの例外の入口**（段階4の実装で生じた項目）
  RP!で負の値にすると、次の語で例外3になるが、入口で戻り先を積む場所がない。
  案：「積めない」とみなして二重例外にする。現在の実装はこの案。
  決定：案のとおり（二重例外）。2026-11-14
- [x] **T-90　スタック深さの判定と、レッドゾーン・SP!の関係**（段階4の実装で生じた項目。仕様の矛盾）
  v0.5の「語を始める時点の深さが範囲外なら例外」（T-13・T-01）と「ベクタ先の語のフェッチで例外なら二重例外」（T-31）を合わせると、次の不具合が起きる。
  - リターンスタックが容量いっぱいで例外が起きると、入口がレッドゾーンに積み、ベクタ先の語を始める時点で深さが容量を超えているので二重例外になる（レッドゾーンが役に立たない）。
  - SP!・RP!で範囲外にした後の例外も、ベクタ先で同じ理由で二重例外になる。
  案（現在の実装）：
  1. 語の中の判定は、命令ごとに「深さが増えて容量を超えた」ときにあふれ、「取り出すときに足りない」ときにアンダーフローとする（深さを増やさない命令は、容量を超えた深さでも実行できる）。
  2. 語を始める時点の深さは、SP!・RP!を実行した直後の語だけ判定する（T-13を満たす）。
  3. 例外の入口の後のベクタ先の語では、始める時点の深さを判定しない。
  4. SP!で物理的な段数より深くした段から取り出した値は0（シミュレータを決定的にするため）。
  決まったら、仕様書6.2.1節・7.1節の判定の書き方を直す。
  決定：案の1〜4をすべて採用。仕様書6.2.1節・7.1節を直した。2026-11-14

  決定：案のとおり（ヘッダなし。コア0のローカルBSRAMの先頭に置き、先頭が入口）。データを外部RAMに置くのはOS自身が行う（仕様書11.2節）。2026-11-14
- [x] **T-43　スタックのあふれ（例外0〜3）の回復の方法**
  ブートROMの雛形には「退避・回復して RTI」とある。退避先をどこにするか。
  案：当面は回復せず、FAULTとして扱う。
  決定：案のとおり（当面は回復せず、FAULTとして扱う）。2026-11-14
- [x] **T-44　ROMのモニタの機能**
  案：レジスタとスタックの表示、メモリのダンプ、続行。UARTで操作する。
  T-41により、外部RAMの全域の検査のコマンドも入れる。
  決定：案のとおり（レジスタとスタックの表示、メモリのダンプ、続行、外部RAMの全域の検査。UARTで操作）。コマンドの書式は実装時に提案する。2026-11-14

- [x] **T-95　ROMのモニタのコマンドの書式、作業領域、RAMエラーのLED**（段階6の実装で生じた項目）
  案（現在の実装）：
  - プロンプトは `> `。1文字のコマンドで、英小文字も受け付ける。CR・LF・空白は無視する。
    `R`＝レジスタ（ECAUSE、EPC、EIR、ESLOT、EADDR）、`S`＝退避したデータスタック（深さと、下からの要素）、
    `D 番地`（CRで終わり）＝その番地から4語×2行のダンプ、`G`＝続行（データスタックを戻してRETI）、
    `T`＝外部RAMの全域の検査（`RAM OK` または `RAM ERROR $番地`）、それ以外は `?`。
  - 入ったときに `*** MONITOR TID=xxxxxxxx` とレジスタを表示する。
  - データスタックの退避先（作業領域）は外部RAMの最後の4KB（全域の検査の対象外）。モニタは同時に1つのスレッドだけが使う前提。
  - 外部RAMの検査で食い違ったときのLEDは 0x2A（101010）。
  制限：BRKで入って `G` で続行すると、同じBRKをもう一度実行する（BRKの戻り先は語の先頭のため）。
  データスタックが一杯（16段）のときに入ると、退避の途中であふれる。
  決定：案のとおり。2026-11-14
- [x] **T-96　予約のSYSCALL番号（4以上）**（段階6の実装で生じた項目）
  案：FAULT（例外番号8）としてカーネルに送り、スレッドを止める。現在の実装はこの案。
  決定：案のとおり。2026-11-14
