# サンプルプログラム

Stack CPU のアセンブリ（`.asm`）のサンプル。CPUとマシンの仕様は [`docs/spec.md`](../docs/spec.md)、シミュレータの画面は [`docs/ui.md`](../docs/ui.md)、UARTの使い方は [`docs/uart.md`](../docs/uart.md) を参照。

どのサンプルも、ソースの先頭のコメントに内容と使い方を書いてある。各関数には、スタック効果 `( 前 -- 後 )` と、使うスタックの深さ `D+n R+m` を書いている（呼び出し規約は `docs/spec.md` の13.5節）。

## 一覧

| ファイル | 内容 | 起動の仕方 | 使うもの |
|---|---|---|---|
| [01_sum.asm](01_sum.asm) | 1＋2＋…＋10 を計算して、ユーザー変数0に入れる（55） | 直接実行 | ループ、リターンスタック、ユーザー変数 |
| [02_max.asm](02_max.asm) | 2つの数の大きい方を返すサブルーチン | 直接実行 | サブルーチン、比較と分岐 |
| [03_uart_puts.asm](03_uart_puts.asm) | UARTに `Hello, world!` を出す | どちらでも | UARTのレジスタ（特権モード） |
| [04_vram_puts.asm](04_vram_puts.asm) | 画面に色付きの `HELLO` を書く | どちらでも | テキストVRAM（特権モード） |
| [05_sleep_joy.asm](05_sleep_joy.asm) | タイマで待ちながらジョイパッドを読み、Aボタンで終わる | 直接実行 | タイマ、WAIT、ジョイパッド、SYSCALL（一般モードでも動く） |
| [06_start.asm](06_start.asm) | 最小のカーネル。tid 1 で一般モードのアプリを起動し、終了を待つ | どちらでも | START、メールボックス、保護キー、SYSCALL |
| [07_adder.asm](07_adder.asm) | UARTから受け取った数字を足し、合計をUARTと画面に出す | どちらでも | SYSCALL（DGETC・DPUTC）、画面のスクロール、10進の表示 |
| [08_vram_random.asm](08_vram_random.asm) | 1秒に1回、ランダムな位置・色で文字列を出す。30回ごとに画面を消す | どちらでも | タイマ、乱数（xorshift32） |
| [09_clock.asm](09_clock.asm) | 画面いっぱいのアナログ時計。UARTから時刻を合わせる | どちらでも | タイマとUARTを同時に WAIT、固定小数点の三角関数 |

「起動の仕方」の意味は次の節。「どちらでも」は、ブートROMから起動しても、直接実行してもよい。

## 動かし方

### シミュレータ（ブラウザ）

1. リポジトリの最上位で `npm run serve` を実行し、ブラウザで `http://localhost:8000/` を開く。
2. 「開く…」でサンプルの `.asm` を選ぶ。ブラウザの中でアセンブルされる（誤りがあれば行番号つきで表示する）。
3. 読み込みの画面で、起動の仕方を選んで「読み込む」。

   | 起動の仕方 | 動作 |
   |---|---|
   | ブートROMから起動 | プログラムをOSイメージとして 0x0010_0000 に置き、リセットから始める。UARTに `Welcome to Stack CPU` が出てから、tid 0 がプログラムの先頭へ移る（実機と同じ流れ） |
   | tid 0 で直接実行 | ブートROMの起動の処理を飛ばし、tid 0 がプログラムの先頭から特権モードで始める。UP（ユーザー変数の場所）は既定で 0x0010_5F80 |

4. 「▶ 実行」（F5）で動かす。時計など、時間に合わせて動くサンプルは、速さを「**実時間**」にする。

- **キーボードの入力：** UARTのタブの黒い端末をクリックしてから打つと、UARTの受信に送られる。画面（キャンバス）をクリックすると、キーがジョイパッドになる（矢印・Z＝A・X＝B・Shift＝SELECT・Enter＝START）。どちらも実行中に入力する。
- **様子を見る：** スレッドの一覧で行を選ぶと、逆アセンブル・スタック・CSR・メールボックスがそのスレッドの表示になる。ステップ実行、ブレークポイント（番地・例外・書き込み・メッセージの到着）も使える（`docs/ui.md`）。

### コマンドライン（アセンブルだけ）

```sh
npm run asm -- examples/07_adder.asm                       # リスティングを表示
npm run asm -- examples/07_adder.asm -o out.bin --hex out.hex   # バイナリと $readmemh 形式
```

`.bin`・`.hex` もシミュレータの「開く…」で読み込める（読み込む番地を指定する。既定は 0x0010_0000）。

### 実機

OSイメージをコア0のローカルBSRAMの先頭（0x0010_0000）に置けば、ブートROMから起動する（`docs/spec.md` 11.2節）。ただし、実機でイメージを読み込む方法（QSPIフラッシュから読めるか）はまだ決まっていない。

## 各サンプル

### 01_sum.asm — 1から10までの和

- **内容：** 1＋2＋…＋10 を計算し、結果（55＝0x37）をユーザー変数0（`ST 0,U`）に入れて HALT する。
- **起動：** 「tid 0 で直接実行」。ブートROMから起動すると UP が0のままなので、0番地への書き込みでバスエラーになる。
- **確かめ方：** 止まったら、メモリのタブで番地 `00105F80`（既定のUP）を見ると `00000037`。
- **ポイント：** ループの数をリターンスタックに一時的に退避する（`PSHR`・`PULR`）。最初に読むのに向いた短いプログラム。

### 02_max.asm — 大きい方を返すサブルーチン

- **内容：** `max ( a b -- m )`（符号付きの比較）で 3 と 1000 の大きい方を求め、ユーザー変数0に入れて HALT する。
- **起動：** 「tid 0 で直接実行」（理由は01と同じ）。
- **確かめ方：** 番地 `00105F80` が `000003E8`（1000）。「飛ばす」（F11）で `BSR max` を1回で実行してみるとよい。

### 03_uart_puts.asm — UARTに文字列を出す

- **内容：** UARTの STATUS（送信FIFOが一杯か）を見ながら、DATA に1文字ずつ書いて `Hello, world!` を出す。
- **起動：** どちらでも（I/Oを直接使うので特権モードで動かす）。
- **確かめ方：** UARTのタブに `Hello, world!`。ブートROMから起動すると、その前に `Welcome to Stack CPU` が出る。

### 04_vram_puts.asm — 画面に色付きの文字列

- **内容：** テキストVRAM（0xFF01_0000）の5行・10桁に、背景1（青）・文字色14（黄）で `HELLO` を書く。
- **起動：** どちらでも（特権モード）。
- **確かめ方：** 画面のタブ。VRAMは1文字2バイト（文字コード、属性）で、属性は上位4bitが背景色、下位4bitが文字色。

### 05_sleep_joy.asm — タイマで待ってジョイパッドを読む

- **内容：** 約1/60秒ずつタイマで待ち（`WAIT` で止まって待つ）、ジョイパッドのAボタンが押されていたら SYSCALL の EXIT で終わる。
- **起動：** 「tid 0 で直接実行」。画面をクリックしてから **Z**（Aボタン）を押すと終わる。EXIT の後、tid 0 はブートROMの idle に入る。
- **ポイント：** ユーザーページ（0xFF0F_0000）のタイマとジョイパッドだけを使うので、一般モードのアプリとしても動く（テストでは、カーネルから START で一般モードで起動している）。64bitのカウンタの読み方（上位→下位→上位）も参考になる。

### 06_start.asm — 最小のカーネル

- **内容：** ローカルBSRAMの保護キーを設定し、tid 1 に START を送って一般モードのアプリを起動する。アプリは `Hello from tid 1` を出して EXIT(7) で終わり、カーネルは EXITED のメッセージを受け取って `EXIT` を出し、終了コードをスタックに残して HALT する。
- **起動：** どちらでも。
- **確かめ方：** UARTのタブに `Hello from tid 1` と `EXIT`。tid 0 のデータスタックに 7 が残る。
- **ポイント：** スレッドの起動（ブートROMの idle と START、`docs/spec.md` 11.3節）、一般モードと保護キー、SYSCALL の流れが分かる。

### 07_adder.asm — 数字を足していく

- **内容：** UARTから1桁の数字を受け取るたびに足し、`+3 = 3` のように UART と画面の両方に出す。数字以外は無視する。画面は30行を超えたら SCROLL で送る。
- **起動：** どちらでも。UARTのタブの端末をクリックして数字を打つ。
- **注意：** 1文字ごとに約10文字を表示するので、数字をまとめて貼り付けると、UARTの受信FIFO（16バイト）があふれて取りこぼす。キーを打つ速さなら問題ない。
- **ポイント：** ブートROMの SYSCALL（DGETC・DPUTC）、`U/MOD` を使った10進の表示（除算器のない構成ではブートROMがソフトで実行する）、変数をプログラムの中に置いて `LEA 名前,PC` で番地を得る書き方。

### 08_vram_random.asm — ランダムな位置に文字列

- **内容：** 1秒に1回、画面のランダムな位置に、ランダムな文字色（1〜15）で `Example of TEXT VRAM` を出す。30回出すごとに画面を消す。
- **起動：** どちらでも。速さを「実時間」にする。
- **ポイント：**
  - タイマの比較値に1秒ずつ足していくので、表示にかかった時間で周期がずれない。
  - 乱数はソフトの xorshift32。種はリセットからの時間（シミュレータでは毎回同じ並びになる）。
  - 乱数を 0〜n−1 にするのに、乱数×n の上位32bit（`MULU`）を使い、除算を使わない。

### 09_clock.asm — アナログ時計

- **内容：** 80桁×30行の文字で、ほぼ画面いっぱいに文字盤（目盛りと1〜12の数字）を描き、短針 `#`（黄）・長針 `*`（水色）・秒針 `.`（赤）を毎秒描き直す。最下行に `HH:MM:SS`（24時間制）。
- **起動：** どちらでも。速さを「実時間」にする。起動した瞬間が 00:00:00。
- **時刻の合わせ方：** UARTのタブの端末に4桁（HHMM）を打つ。1時1分なら `0101`。打ち終えるとその時刻の0秒から数え直し、UARTに `0101 OK` と返す。ありえない時刻（時が24以上、分が60以上）は無視して ` ?` を返す。数字以外のキー（Enterなど）は打ちかけの数字を捨てる。
- **ポイント：**
  - 文字が縦長（8×16ドット）なので、横の半径（28桁）を縦の半径（14行）の2倍にして円に見せる。
  - sin の表（6度ごと、256倍）で針の点を計算する。符号付きの右シフトがないので、正の値にずらしてから論理シフトする。
  - タイマ（イベント2）とUARTの受信（イベント4）を1つの `WAIT` で同時に待つ。

### 10_clock_mt.asm — 3つのスレッドで動く時計

- **内容：** 09をスレッドに分け、画面の左上に大きな数字のデジタル時計（HH:MM、コロンは1秒ごとに点滅）を加えたもの。

  | スレッド | 役目 |
  |---|---|
  | tid 0 | 時間の制御とUARTの入力。tid 1・2 を START で起動し、1秒ごとと時刻を合わせたときに、時刻をメッセージで送る |
  | tid 1 | アナログ時計を描く |
  | tid 2 | デジタル時計を描く |

- **起動：** ブートROMから起動する（tid 1・2 がブートROMの idle で START を待つため）。直接実行しても、他のスレッドは idle で待つので動く。速さを「実時間」にする。時刻の合わせ方は09と同じ。
- **メッセージ：** tag `$7001`（アプリどうしで自由に使う範囲）、本文は時・分・秒の3語。tid 1・2 は、ほかのメッセージが届いたら本文を捨てて無視する。
- **ポイント：**
  - tid 1・2 は `RECV` で止まって待つので、待つ間は番を使わない。
  - 描く場所と変数をスレッドごとに分けているので、排他は要らない。
  - デジタル時計の数字（3×5文字）は、空白の文字に背景色を付けて点にしている（フォントにブロックの図柄がないため）。
  - シミュレータでは、tid 1 のメールボックスのタブで「届いたら止める」を押すと、毎秒のメッセージの中身を確かめられる。

## サンプルのテスト

サンプルの動作は `npm test` で確かめている（主に `test/boot.test.js`）。ブートROMから起動した場合の UART の出力、画面の文字、スレッドの状態などを照合している。サンプルを変えたら、テストも合わせて直す。
